1. Specialization / Generalization — HEALTH_RECORDS

The HEALTH_RECORDS superclass is specialized into 4 subclasses via the record_type discriminator (disjoint, total specialization):

HEALTH_RECORDS (Superclass) │ ├── discriminator: record_type │ ├─── VITALS (bp_systolic, bp_diastolic, heart_rate, blood_sugar_fasting, blood_sugar_random, blood_sugar_pp) │ ├─── SYMPTOMS (symptom_description, severity_level 1-10, duration, body_area, triggers) │ ├─── LIFESTYLE (sleep_hours, exercise_minutes, water_intake_liters, stress_level, diet_quality) │ └─── MEDICATION (medications_taken[], adherence_status, side_effects)

Mapping: Single-table inheritance. All subclass attributes exist as nullable columns in health_records. The record_type ENUM determines which columns are populated.

2. Specialization — SUBSCRIPTIONS

The SUBSCRIPTIONS entity specializes based on plan_type:

SUBSCRIPTIONS (Superclass) │ ├── discriminator: plan_type │ ├─── FREE (billing_amount = 0, limited features) │ └─── PREMIUM (billing_amount = ₹99/mo, unlimited chat, voice, reports, priority API)

3. Specialization — ENVIRONMENTAL_ALERTS

ENVIRONMENTAL_ALERTS (Superclass) │ ├── discriminator: alert_type │ ├─── AQI_SPIKE (aqi_value, pm25, pm10, pollutant levels) │ ├─── HEATWAVE (temperature_celsius > 40°C, humidity) │ ├─── COLD_WAVE (temperature_celsius < 5°C) │ └─── HEALTH_THRESHOLD (triggered by abnormal vitals, not environmental)

4. Aggregation

The relationship between USERS, CHAT_HISTORY, and API_USAGE forms an aggregation:

USERS ──── sends ──── CHAT_HISTORY │ aggregation of │ API_USAGE (tracks tokens, cost, model used per chat message)

Each chat message generates an API usage record via the trg_log_chat_api_usage trigger.

5. Total vs Partial Participation

  • Total: USERS → USER_PREFERENCES (every user MUST have preferences)
  • Total: USERS → SUBSCRIPTIONS (every user MUST have a subscription, at minimum 'free')
  • Partial: USERS → ABDM_INTEGRATIONS (optional ABHA link)
  • Partial: USERS → MEDICAL_REPORTS (users MAY upload reports)
  • Partial: USERS → HEALTH_CONDITIONS (users MAY have conditions)
